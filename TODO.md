## High priority — confirmed defects

1. **[Fixed] DateTime64 overflow on valid dates.** `UnixNano` and the conversion of ticks to nanoseconds corrupted dates beyond the year 2262 even with precision 0/3: `2299-01-01` turned into the year 1714. Writing and reading in both variants now compute seconds and the fractional part separately. The regression `TestDateTime64WideRange` first failed, then passed: precision 0–9, dates 1900/2023/2299 (2299 excluded for precision 9), UTC and Asia/Shanghai, independent wire-write and read checks. The full integration run with the race detector passed.
2. **[Fixed] Variant type order and discriminator.** The constructor sorts a copy of the list by type name without mutating the caller-owned slice. `TestVariantCanonicalOrder` first failed on write, read and metadata, then passed after the fix; the full integration run with the race detector passed. NULL and large discriminators remain separate items.
3. **[Fixed] Early Insert success.** The method waits for the producer result after a successful HTTP response, closes the pipe reader to unblock writing, and honors context cancellation; callback/flush errors are no longer lost. `TestInsertEarlySuccessWaitsForWriter` first failed with nil, then passed 5/5 times; the full integration run with the race detector passed. An arbitrarily blocking callback still cannot be forcibly stopped (item 77). Follow-up: the producer posted its result after closing the pipe, so a cancellation right after a complete upload could still be reported as `context canceled`; `TestInsertSuccessNotMaskedByLateCancel` failed 31/300 runs at `cd2809d`. The result is now posted before the pipe is closed (300/300 passes).
4. **[Fixed] Array length overflow when converting to int.** Both decoders reject lengths above MaxInt before allocating/resizing the slice. `TestArrayLengthOverflow` first reproduced a panic for nil and reused destinations in the generic/Any variants, then passed; the full integration run with the race detector passed. 68. **[Partially fixed] Define limits on input size, depth and memory.** Large but representable collection/string lengths may allocate excessive memory; recursive types have no depth budget. Verify with safe bounded tests. Fuzzing (`fuzz_test.go`) found that array decoders allocated for the declared count before reading (a few bytes declaring 2^40 `UInt8` elements got the process killed for running out of memory) and that maps used the count as a size hint. Fix: arrays grow as elements are read (reusing the destination's capacity) and map hints are capped. Decision and fix for zero-width elements: arrays and maps whose elements take no bytes (`Array(Nothing)`, `Array(Tuple())`, `Map(Nothing, Nothing)`) are limited to 1M elements, as a budget per row in `FormatReader` (so nesting cannot multiply it) and per collection otherwise (`zero_width.go`).
